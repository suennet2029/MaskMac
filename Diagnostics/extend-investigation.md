# Extend 实机排查记录（2026-09-13）

## 未解决的问题与约束

用户确认：开启、关闭 Extend 时外屏均有约十秒黑屏或无信号；恢复内屏后状态栏图标挤压。必须保留硬件断开内屏，不接受镜像加熄屏。当前没有通过用户可见效果验收的修复。

## 本机证据

- Apple M5，RV200 Turbo，用户确认 Mac HDMI 接口直连。开始排查时外屏的 CoreGraphics 渲染尺寸为 5120×2880，逻辑尺寸为 2560×1440，刷新率 120Hz；渲染尺寸不代表 HDMI 实际传输时序。
- 01:34:27.906 提交恢复内屏后，系统曾选择外屏 Mode 94（2048×1152），随后恢复 Mode 111（2560×1440）。内屏坐标也曾短暂成为主屏坐标。这说明提交成功后仍有重新枚举与布局变化。
- 对应内核日志出现 AppleDCPPS190、HDMI FRL 40 Gbps、HPD 状态变化和重新训练。仅凭这些日志不能确定线材或显示器故障，也不能把全部十秒都归为训练时间。
- 之前约 2.37 秒关闭、1.00 秒恢复的数字仅是 CoreGraphics 状态确认时间，用户已明确否认其代表实际画面恢复速度。

## 已排除的方案

1. 在同一事务固定模式与位置：未能阻止外屏后续重新枚举；对刚启用的内屏设置缓存模式还返回 1001。未合入应用，随后使用原始启用事务恢复内屏。
2. 镜像合并桌面：程序侧观察到外屏模式稳定，但用户仍看到长黑屏，且不接受改变硬件断开语义。未合入应用。
3. 临时 60Hz 对照：单独设置返回成功，但内屏切换立即使系统恢复保存的 120Hz，因此该对照无效，不能据此判断刷新率与黑屏的关系。结束后恢复原有配置。

## 后续验证边界

- 应用的刷新计时器、事务返回和活动显示器列表不能测量外接面板真正亮起的时间。
- 状态栏异常尚无图像验收证据；不能直接认定重启 ControlCenter 或追加固定延时可以修复。
- 若继续隔离 HDMI 链路影响，需要在可用时用 USB-C 至 DisplayPort 直连作对照，保持硬件断开语义；不要求购买设备，也不把更换线路预先认定为修复。
